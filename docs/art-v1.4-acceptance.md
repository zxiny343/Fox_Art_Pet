## 1. R1（P0）短尾 / 细尾尾根缺口 —— 已修，这是本次最关键的交付

修法：选了方案 A 的变体「根部短程绒毛过渡」，往 `tail_short.png` / `tail_thin.png`
里按 `alpha = 255·exp(-d/40)` 补写根部绒毛，没有平涂补色、没有改 body_core 窗口。

我方独立实测（产品自己的渲染路径 `artmap._compose`，1024 画布 / 短毛母版）：

| 尾型 | v1.3 缺口 | v1.4 缺口（blue / black / orange / white） |
|---|---|---|
| tail_short | 32,043 | **0 / 0 / 0 / 0** |
| tail_thin | 35,743 | **0 / 0 / 0 / 0** |

溢出母版轮廓的新增像素：**0**（不会在桌宠透明背景上显出一圈毛色雾）。
36 只真实种群批量渲染：最差缺口 2,312 px（阈值 5,000），破面 0 只，降级触发 0 只。

**注 1（形态）**：尾件本体的像素量从 8,044 → 41,121（+411%）、34,229 → 71,639（+109%），
bbox 也从 (270,386) 扩到 (147,297)。这不是形态被改坏——
修法本身就是「往尾巴窗口里填绒毛」，增量和扩框属预期。
新增的 33,077 / 37,410 px 里，半透明（alpha 8–200）占 31,247 / 35,411，
不透明部分只增加 1,830 / 1,999 px —— 也就是说**尾身本体几乎没动**。

## 2. 两个新观察（不阻塞，记入 v1.5 候选）

### 2.1 R1 填充区是「半透明雾」而不是「毛」—— 观感，非可用性

缺口判据只看 alpha < 8，所以「填了但很淡」同样判通过。桌宠是透明背景，
真正要的是这块区域接近实心且有毛流纹理。以 `tail_normal` 在同一窗口作参照：

| 尾型 | 区域 px | alpha 均值 | 中位 | >200 占比 | 亮度 std（纹理） |
|---|---|---|---|---|---|
| **tail_normal（参照）** | 33,077 | **253.2** | 255 | **99.0%** | **70.9** |
| tail_short | 33,077 | **73.3** | 50 | 8.2% | 15.4 |
| tail_thin | 37,410 | **62.1** | 29 | 9.2% | 16.3 |

结论：短尾/细尾的尾根区在成品上是约 25% 不透明度的一片淡毛色，
且几乎没有明暗纹理（std 15 vs 参照 71）。比 v1.3 的破洞好得多（破洞直接露出桌面背景），
但还不是「毛从身体里长出来」。

根因很具体：衰减长度 40 px 相对填充区尺度（约 180×180）太短，
`exp(-d/40)` 在 d>80 就基本归零，于是大片区域只剩 alpha 下限 10。

**建议（若发 v1.5）**：把衰减长度从 40 放到 120–160，或改成分段曲线
（近端实心 → 远端在窗口边缘之外才衰减到 0）；同时把 `tail_normal` 的高频毛流
明暗按现行幅度搬进去，让 std 从 15 提到 60+。不需要改结构。

### 2.2 R2 的改动可测，但对观感的净效果 ≈ 0

像素级 diff（v1.3 → v1.4）：

| 尾型 | alpha 变化 px | RGB 变化 px | 新增不透明 px |
|---|---|---|---|
| twin | 179 | 50,346 | 103 |
| triple | 427 | 58,317 | 303 |
| quad | 468 | 62,571 | 334 |
| quint | 395 | 57,612 | 279 |
| nine | 404 | 55,136 | 302 |
| normal（未动，作基线） | 0 | 0 | 0 |

说明他们确实把根部（半径 110–160 px）的毛流场整体重写了一遍（RGB 变 5–6 万 px），
也填了一点点白缝（新增不透明 103–334 px）。但用「根部窗口内暗于毛色 base 45 级以上的像素数」
这个指标测，v1.3→v1.4 的变化量与 **normal 这个未改动的基线完全同步**
（orange 下 +71/+71/+71 vs normal +73），即针对多尾的净效果测不出来。

考虑到 R2 原缺陷本身就只有几十像素、1× 静态不可见（这也是我在返修单里把它从 P0 降到 P1 的依据），
**这条结案，不再返修**。真要判断得等桌宠动起来——尾巴摆动时如果有闪烁再处理。
返修单里我写「不要用数值卡 R2 观感，用固定角度出图 + 人眼」，这次照做了，
结论是「与基线无统计差异」，不是「变差」。

## 3. 我方为接入 v1.4 改的三处（不动美术文件）

1. **`sim/artmap.py` 新增 `fur_key()`**：v1.3 的中毛母版叫 `fox_fur_mid_blue_q4`，
   v1.4 改名为 `fox_fur_medium_blue_q4`（R6）。现在按磁盘实际存在者自动选，
   同一套映射层能同时跑 v1.3 与 v1.4。表型侧 id 仍统一用 `mid`，磁盘名解析交给它。

2. **`sim/render_kernel.py` 降级表按素材版本自动失效**：
   新增 `_art_ver()` / `_retire_degrade_rules()`，素材包 ≥ 规则里写的 `until` 版本时
   自动 `enabled=False`。v1.4 到位后三条降级（thin→normal / short→normal / large→round）
   全部自动停用，实测 36 只降级命中 0。**不用再靠"记得手动改"**。

3. **两个验收脚本改成版本自适应**：`verify_render_kernel.py` 的 A 段原先断言
   "必须降级"，在 v1.4 上会把"修好了"判成失败（8 项误报）。
   现在按 `ART_VER_NUM` 分支断言，两种情况都有意义。
