## 1. R1（P0）短尾 / 细尾的尾根缺口

### 1.1 现象

用你的 `run_assemble.py` 组装后，`tail_short` 与 `tail_thin` 在**尾根到身体之间**会破开一大块透明区，
成品里看到的是「身体被削掉一片、露出背景」。缺口面积约 3.2–3.6 万像素（1024 画布），
在这个尺寸下是眼睛一眼能看到的硬伤，不是瑕疵。

证据图：`fix-evidence-tails-v1.4.png` A 段（红色 = 缺口像素），short / thin 两张红成一片。

### 1.2 实测数据（统一条件 coat=blue / ear=large / eye=round_blue）

| 尾型 | 缺口像素 | 判断 |
|---|---|---|
| normal / triple / quint / nine | **0** | 正常 |
| fluffy | 777 | 可忽略 |
| twin | 1,292 | 轻微 |
| long | 2,055 | 轻微 |
| quad | 2,679 | 轻微 |
| curl | 8,295 | 偏大 |
| **short** | **32,043** | **必须修** |
| **thin** | **35,743** | **必须修** |

### 1.3 根因（我们的分析，供参考）

1. `body_core` 把整块尾巴区域切成了窗口，面积约 **40,294 px**；
2. 兜底片 `tail_base_<coat>@1024.png` 只覆盖 socket 本体（约 **3,181 px**），**没有覆盖整个尾巴窗口**；
3. `tail_normal` 这类大尾巴自身就填满了窗口，所以看不出问题；`tail_short`（232×119）、`tail_thin`（184×351）
   毛量少，**填不满窗口，缺口又与外部背景连通**（不是封闭洞）；
4. 因此你的自修复 `repair_pockets`（`binary_fill_holes`）**填不到它**——实测 `pocketRepairPx`：
   twin 565 / quad 141 / triple 5 / **short 0 / thin 0**；
5. 同一原因，`run_batch.py` 的「单连通域」检查也是 PASS（连通域确实只有 1 个，缺口是通向外部的豁口），
   **回归因此漏掉了这个 P0**。

### 1.4 建议修法（按推荐顺序，选一个即可）

**方案 A（首选，改动最小，只碰 2 个文件）**
把 `tail_short` / `tail_thin` 的**根部毛量加宽**，使其自身覆盖满 `body_core` 的尾巴窗口：

- 保持尾身中远端的形态不变（short 仍然短、thin 仍然细，这两件的卖点不能丢）；
- 只把 socket (`socketBBox = (208,298)-(503,506)`) 往外 **60–100 px** 范围内的根部做成渐变加粗的过渡，
  毛流方向接着 `tail_normal` 的根部走，看起来像「毛从身体里长出来」，而不是贴了一块补丁。
- 目标：缺口像素 **< 500**。

**方案 B（如果 A 做不出自然过渡）**
为这两件各出一张专属兜底片：`tail_base_short_<coat>@1024.png` / `tail_base_thin_<coat>@1024.png`，
形状 = 通用 `tail_base` 与「该尾形根部实际毛量」的并集，覆盖整个尾巴窗口。
缺点是 12 个毛色要各出 2 张（24 张），除非你改成运行时按 `coat` 动态换色。

**方案 C（不推荐，但可行）**
把 `body_core` 的尾巴窗口从矩形改成「沿 `tail_normal` 轮廓外扩 3 px 的掩膜」，并按尾型分档。
这会动 12 个 `body_core`，回归面太大，除非你想顺手重构。

> **请不要用「把缺口当洞填成纯色」的方式收尾。** 缺的那块正是毛流最密的地方，
> 平涂一块会立刻被看出来，比现在更显眼。要的是毛量过渡，不是补丁。

### 1.5 验收标准

- 在 1024 画布、`coat=blue` 与任意一个深色（`black` 或 `haze_blue`）两个条件下，
  **「母版轮廓内、组装后却是透明」的像素 < 500**（short / thin 各测一次）；
- `tail_short` / `tail_thin` 的尾身 bbox 与 v1.3 相比变化 **< 3%**（形态不能变）；
- `_tail_counts.png` 里 short / thin 两格根部无破面（1× 与 2× 放大各一张）。

## 2. R2（P1）多尾分支根部的深色碎片与接缝线

### 2.1 现象

多尾是「单个 `tail_normal` 旋转复制」做的（思路没问题），但每个副本都带完整的闭合描边。
在锚点 `(425,505)` 附近，相邻分支的描边互相叠压，结果是：

1. 根部出现一块**被描边围起来的深色碎片**（不是毛，是若干圈描边挤在一起）；
2. 分支之间留下 **1–2 px 的白色缝隙**（描边都没覆盖到的空隙），在蓝毛中间像一根白头发；
3. `twin` 起就有，`nine` 分支最多、最明显；`normal` 完全干净。

证据图：`fix-evidence-tails-v1.4.png` B 段（normal / twin / nine 三列 2.8× 对照）。

### 2.2 严重度说明（为什么是 P1 而不是 P0）

我最初按「1× 下读作脖子后黑斑」判了 P0，实测后**下调为 P1**，依据是：

- 1× 静态下这块碎片只有几十个像素，不影响可用性，也谈不上"破面"；
- 但我试了几种自动指标（窗口内暗像素占比、模糊后低分位亮度）都区分不开正常与异常，
  说明它在像素统计上很小——**所以本项请以目视放大图为准，不要用数值卡**；
- 仍建议修的原因：桌宠会放大显示，且尾巴摆动时这块碎片和接缝会随之闪烁，动态下比静态显眼；
  而多尾正是我们最核心的可见进化信号。

### 2.3 根因

N 条分支 = N 圈描边在锚点附近重叠；分支越多，重叠越密，缝隙也越多。

### 2.4 建议修法

**方案 A（首选：先合形，再统一描边）**

1. 先把每个分支的**根部段（距锚点约 60–80 px 内）的闭合描边去掉**，只留填充（或留单侧轮廓）；
2. 分支合并成一个整体 alpha 形状，合并处不留缝；
3. 对合并后的整体形状**统一跑一次 outline pass**，得到唯一一条外轮廓。

这样从数学上只会有 1 条外轮廓，根部不可能叠色，白缝也一并消失。

**方案 B（改动更小：根部遮罩）**

在距锚点半径 ~90 px 内，用 `base` 色 + 羽化（feather 12–20 px）把内部描边压掉，只保留最外层轮廓。
实现简单，但半径选不好会出现「一块模糊的球」，需要目视调。

**方案 C（只在分支多时退化）**

分支数 ≥ 5 时把单分支描边宽度从 3–4 px 降到 2 px。治标，9 尾仍可能残留接缝，建议只作为 A 的兜底。

### 2.5 验收标准

- 1024 画布、`coat=orange` 与 `coat=mist_purple`（这两种浅色毛最能暴露问题）；
- 以锚点 `(425,505)` 为中心取 200×200 窗口，**2.8× 放大后**：
  根部不出现「被描边围起来的深色碎片」，毛面上不出现跨越的白色细缝；
- 出 `_tail_root_fix.png`：`normal / twin / quint / nine` 四列 × 两个毛色，同一窗口放大对照。

## 3. R3（P1）`ear_large` 的体量语义反转

### 3.1 现象

Ez 位点是「耳朵大小」三档：`0 = small` / `1 = round` / `2 = large`。
但实测内容（alpha > 8 的像素统计）：

| 部件 | 内容 bbox | 内容像素 | topY |
|---|---|---|---|
| `ear_small_L` | 129×167 | 16,344 | 169 |
| `ear_round_L` | 161×167 | 21,103 | 169 |
| **`ear_large_L`** | **125×101** | **6,054** | **235** |

`ear_large` 的内容**只有 `ear_small` 的 37%（小 2.7 倍）、`ear_round` 的 29%（小 3.5 倍）**，
而且整体**下沉了 66 px**，看起来像「贴在头侧的一片薄月牙」而不是一只大耳朵。
证据图：`fix-evidence-ears-v1.4.png`（同一 1024 坐标，1:1 未缩放）。

这个问题从 v1.2 就在，v1.3 没动过它。

### 3.2 建议修法

以 `ear_round` 为母本**重绘大耳**，目标是「同一只狐的放大版耳朵」，而不是把 round 直接放大
（直接缩放会让 3–4 px 描边变成 4.5–5.5 px，和全身笔触不一致）：

- 内容面积：`small < round < large` **单调递增**，建议 `large` 内容像素 ≈ 28,000–32,000（round 的 1.3–1.5 倍）；
- `topY` 与 `small`/`round` 一致（**169 ± 4**），不要下沉；
- 耳内绒毛、内耳色、毛流走向沿用 round 的画法；
- 左右两件都要改（`ear_large_L` / `ear_large_R`），`requiresPair` 规则不变。

> 如果你们原本就想做「大而薄的狐耳」这一种设计，也请先告知——
> 那样的话产品侧会把 Ez 的语义从「大小」改成「形状」，改的是我们这边，你们不用返工。
> **但默认请按「大 = 更大」修**。

### 3.3 验收标准

- 三件内容像素单调递增，`large / round ∈ [1.25, 1.6]`；
- 三件 `topY` 差 **≤ 6 px**；
- 出图 `_ear_sizes.png`：三件 1:1 并排 + 各自组装到同一只蓝狐上的对照。

## 4. R4（P1）花纹遮罩覆盖率偏低

实测在躯干区间内，花纹层的有效覆盖：

| 花纹 | 躯干覆盖率 |
|---|---|
| `pattern_stripes` | 22% |
| `pattern_tabby` | 22% |
| `pattern_spots` | 9% |

在 512 上看还行，但桌宠实际显示尺寸是 **128–256 px**，缩下去以后花纹只剩一层淡纹理，
`P` 位点（条纹/虎斑/斑点）几乎是白设计。

### 建议

- 把 `stripes` / `tabby` 的躯干覆盖率提到 **≥ 40%**，`spots` 提到 **≥ 25%**；
- 优先**加粗笔画 / 增加条数**，不要靠加深颜色——颜色是随毛色 `shade` 自动取的，改深了在浅色毛上会脏；
- 保留现有的「面部保护椭圆」逻辑（不上脸），这一点 v1.3 做得对。

### 验收

- 出 `_pattern_scales.png`：条纹/虎斑/斑点 × 128 / 256 / 512 三档缩略，
  **128 px 下仍能分辨三种花纹的区别**；
- 各配 1 个深色毛（black）+ 1 个浅色毛（white）对照。

## 11. 我们这边怎么验收
