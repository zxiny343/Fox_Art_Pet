02本轮改了什么

在 E1–E5 全部采纳的基础上，另有五处改动（C1–C5）与两个缺陷修复。下面每条都写清了怎么发现的，因为其中三条完全靠肉眼标高 invalid。

C1｜修掉「静默裁剪幼崽」—— 改为整窝名额预留

怎么发现的：给 v0.4 补观测指标时，看到 trimmed_pups = 1292 ——每 20 年有 1292 只已经受孕的幼崽被名额规则静默丢弃，是实际出生数（692）的 1.9 倍。表现到产品上就是：玩家看到一只怀孕的狐狸，最后只生下来 1 只。

改法：受孕前检查剩余名额，不足一整窝（默认 6）就干脆不受孕。

Cap_mode       = L_plus_reserve
Litter_reserve = 6            # 剩余名额 < 6 就放弃本次妊娠
副作用必须知道，而且不小：把「整窝」作为受孕前提，等于把有效容量从 40 降到约 34，窝数从 442 降到 112（−75%），出生总数也下降约 27%（692 → 502）。
但换来的是每一窝都是完整的：每窝平均仔数从 1.56 只升到 4.47 只，且被静默丢弃的幼崽归零。
换句话说，v0.4 的「高出生」是靠 442 次妊娠堆出来的，其中 1292 只胎儿直接被扔掉；v0.5 的 112 次妊娠全部走完。对玩家而言这是净改善：一窝兄妹摆在一起才看得出 3:1，而不是隔三差五蹦出一只独苗。
代价要如实记着：周转率下降，世代推进从 38 代放慢到 28 代（−26%）。

C3｜野外引入升级为「异地互补基因库」

v0.4 的引入用创始基因库同频率抽等位基因 —— 带进来的多是种群里已经有了的等位，效果被自己打折了。改为按「当前种群里越稀缺、引入概率越高」加权，等价于保护遗传学里挑选无亲缘建群者的标准做法。

Immigration_pool   = complement   # 异地互补基因库
Immigration_sex    = balance      # 补稀缺性别（随机性别会浪费掉一半引入个体）
Immigration_mode   = days         # 按固定天数推进，避免世代停滞时彻底断流
Immigration_every_days = 14 游戏天
这是本轮收益最大的一条改动。在同样外部的前提下，互补库把 20 年后的近交从 0.235 压到 0.097，同时毛色种类从 3.6 提升到 4.8。

C4｜突变判定单位：每窝 → 每只幼崽

真实突变发生在配子/合子层面。原实现「每窝摇一次骰子，最多一只突变」有两个后果：突变总量被窝数人为压低；而且永远看不到「同一窝里出现一只突变兄妹」 —— 这恰恰是最能体现孟德尔随机性、也最有节目效果的画面。

UI 文案要跟着改：设置项必须写清楚是「每只幼崽的突变概率」，否则用户会按「每窝」理解，实际观感会比预期频繁。

C5｜迁徙强度 0.00025 → 0.00003 / 游戏小时

把寿命调到 55 天那组做长期测试时发现：20 年内有 77 只迁徙离场，比死亡总数还多。根因是迁徙判据里有一条「适应度低于种群均值 −0.05 就 ×3」，而低于均值的个体恒占约一半，叠加长寿命带来的更长暴露时间后，几乎所有成体最终都会离场 —— 这违背了 Q7 把迁徙定位为「补充性非死亡退出机制」的初衷。回调后迁徙占离桌总数稳定在 20%。

顺带修掉的两个缺陷

缺陷 A：引入个体不检查胎儿配额，会冲破硬上限
现象：某一组配置下出现 峰值 41 > 上限 40，直接违反需求第七条。
原因：繁殖逻辑用 N_eff = 存活数 + 在孕胎儿数 做配额检查，但引入逻辑只看存活数。于是「38 只活着 + 3 只胎儿」时被判定还有余量，又把一只野外狐狸放了进来。
修复：两者统一走同一个 n_eff。修复后在全部 2000+ 次搜索运行中，峰值再未超过上限。
工程教训：凡是「同一份资源有两种使用者」的地方，必须强制共用同一个余量函数。这里是繁殖 vs 引入；同类风险还有快照回滚 vs 实时写入。
缺陷 B：被阻断的妊娠也被计入了窝数
litters += 1 写在受孕函数开头，而名额检查在后面，导致「根本没怀上」也算一窝。修复前出现过「443 窝但只生出 180 只」的荒谬读数。

04参数寻优过程

4.1 种群上限不需要再往上调

原本预期上限 40 → 50/60 能进一步改善多样性，实测并没有。

数量上限世代近交 F外观指纹毛色窝数末种群
上限 3026.60.1520.884.837926
上限 4028.20.0970.854.8311235
上限 5029.20.1390.834.7514345
上限 6031.60.1440.805.0017454
原因：多样性由基因流入速率主导，而引入节奏是按时间推进的、不随 N 缩放。所以 40 是一个很好的默认值，更高的上限只会线性增加渲染与 CPU 开销，买不到多样性。

4.2 世代推进的天花板在哪

我们试过缩短世代间隔（幼崽 96→72 小时成年、繁殖间隔 72→48 小时）来追回世代数，结果收效甚微：世代推进其实被周转率封顶了 —— 稳定状态下出生数必须等于死亡数，而死亡数由「种群规模 ÷ 寿命」决定。在只想不抬高近交的前提下，20 年 28 代左右就是这个结构的上限。

4.3 三档「演化节奏」预设

既然不能两头都占，就把选择权做进产品：三档的差异只在观察节奏，多样性几乎等价。

05仍然存在的三个风险

风险 1：自然选择本轮依然等于没跑
实测选择强度 r = 0.028（纯噪声水平）。这不是缺陷 —— 「食物充足 + 环境适宜 + 不会饿死」翻译成生态学语言就是没有选择压力。

但这是一个产品陷阱：如果 UI 直接显示「当前选择强度」这个数字，玩家会在很长一段时间里看到 0，从而误以为「族群进化」是假的。
建议在显示这个数的同时，必须给出制造压力的入口：季节强度、投喂开关、壁纸明暗，并把它们做成同一个「环境压力」面板。
风险 2：§15 取食系统本轮一次都没触发
休眠事件计数在所有轮次均为 0 —— 因为「食物充足」是本次模拟的前置条件。这条功能等于还没有被真正测过，必须单独补一轮「食物短缺」场景再定它的参数，尤其是饱食度下降速率、休眠阈值、以及苏醒后的恢复曲线。
风险 3：40 只同屏的性能开销没有被覆盖
离线模拟完全不涉及渲染。v0.4 那轮的这块风险本轮依旧成立。
从文字上看，40 只狐狸同时显示在桌面上意味着 40 个半透明无边框窗口，即使按 §7 的 LOD 分级（远距离个体降到 12 fps、隐藏粒子特效），窗口本身的合成开销仍然存在。必须先做一个 40 只同屏的技术验证再定默认值。若实机顶不住，优先降到 30（仍有 26.6 代 / 20 年），但不要动引入节奏——那是多样性的唯一来源。
