# 动画播放器原型 v1（2026-11-02）

读 `01_Data/skeleton.json`（20 骨 + 9 插槽）与 `animations.json`（36 动作 / 30fps /
base·add·face 三层），把 artmap 的成品图按骨骼姿态驱动。

**结论：待机动画已跑通，尾巴摆动 + 耳朵抖动 + 呼吸 + 眨眼四层叠加可用，
36 个动作里 18 个可以直接播，另外 18 个受素材结构限制做不了（见第 3 节）。**
自检 `verify_anim.py` 14/14、`verify_anim_data.py` 数据体检 3/6（3 项失败是真实数据问题）。

---

## 1. 实现方式与为什么这么做

美术交付的是**整张 1024 部件位图**（尾巴一张、耳朵一张、身体一张），
不是 Spine 那种分槽网格。这决定了能做什么：

| 能力 | 做法 | 状态 |
|---|---|---|
| 尾巴摆动 | 沿主轴分 3 段，链式刚性旋转（段 i 累积前 i+1 关节） | ✅ |
| 耳朵抖动 | 整件绕耳骨 start 旋转 | ✅ |
| 呼吸 | 绕 pelvis 做 X/Y 缩放 | ✅ |
| 眨眼 | eye_l/eye_r 插槽按关键帧切换附件 | ✅ |
| 头部相对身体转动 | 需要切割 body_core | ❌ 见第 3 节 |
| 四条腿独立迈步 | 需要分腿部件 | ❌ 见第 3 节 |

**尾巴分 3 段的依据**：骨骼链是 `tail_root → tail_mid → tail_sub → tail_tip`，
但 `tail_mid` 与 `tail_sub` 的 start 重合（都是 (312,415)），
所以合并成一段，实际 3 段。分段阈值用像素沿主轴的投影距离：
`root→mid 144px`、`mid→sub末 218px`、`之后到尾尖`。段间各外扩 8px 重叠，实测不撕裂缝。

**不做网格蒙皮（LBS）**：桌宠实际显示 128–256px，头部转 5° 在 256 下只有约 3px 位移，
收益小于实现与调试成本。原型阶段先验证数据，不做。

## 2. 性能

第一版在 1024 上做全画布旋转：**0.92s/帧**。三处优化后：

| 优化 | 效果 |
|---|---|
| 每层裁到内容 bbox 再旋转，转完贴回原位 | 0.92s → 0.17s（省 5–10 倍） |
| 变换发生在工作分辨率上（不是 1024） | 256 工作流 → 0.036s |
| 眼睛整层按 (眼件组合, 分辨率) 缓存，只眨眼那帧重算 | → 0.011s |

| 工作分辨率 | 帧耗时 | 等效帧率 | 与 1024 参考的画面差 |
|---|---|---|---|
| 256（桌宠默认） | **9.3 ms** | **107 fps** | 不透明区平均差 9.4/255 |
| 512 | 42.5 ms | 24 fps | 4.6/255 |

桌宠显示 256 时直接用 work=256 输出，没有缩放损失。
更进一步可以预渲染帧序列、运行时只贴图（<1ms），但当前性能已经够 30fps。

## 3. 限制（素材结构决定的，不是播放器能解的）

### 3.1 18/36 个动作需要"单独变换的腿"

`walk / run / jump / sit_down / roll_over / stretch / scratch / play_bow / drag / drop`
等 18 个动作驱动 `hip_* / foot_* / shoulder_* / paw_*`（四条腿）或 `root`（整体位移）。
但**四条腿和躯干在同一张 `body_core` 位图里**，无法单独旋转。

这些动作现在会退化成"只有尾巴和耳朵在动，身体不动"——不会报错，但走路看不出来。

要支持它们，需要美术提供**分腿部件**（或分腿掩膜）。
我的建议：**桌宠 MVP 不需要**。待机 + 摇尾 + 眨眼 + 歪头 + 被摸反应已足够"活"，
走路属于加分项，等 MVP 跑起来再决定是否要 v1.5 求这套部件。

### 3.2 头部相对身体转动需要切割 body_core

`nod / tilt_head / shake_head / howl` 用 `head` 或 `neck` 骨。
头和身体在同一张位图上，切割后绕颈点旋转会在分割线处露缝（远离颈点处位移可达 13px）。
原型阶段未做。真要做建议改走网格变形（LBS），而不是刚性切割。

### 3.3 多尾分支的相位差没实现

`animations.json` 给 `tail_triple/quad/quint/nine` 提供了逐分支骨骼
（`tail_b{i}_{root|mid|sub|tip}`），分支 i 相位 +0.05·周期、振幅随分叉角衰减。
但 N 条尾巴画在**同一张 PNG** 里，要独立摆动就得按角度扇区切分，
根部会重叠。原型阶段所有分支同步摆（用单尾骨骼链）。

## 4. 数据体检发现的问题（要反馈给美术）

`sim/verify_anim_data.py` 的结果，3 项失败都是真实问题：

### 4.1 `eye_closed` 缺 mist_purple / haze_blue（真缺陷，建议 v1.5 补）

12 个毛色里 10 个有 `Expressions/eye_closed_<coat>.png`，
**v1.4 新增的两个稀释色（mist_purple / haze_blue）没有**。
这两个毛色的狐狸眨眼时会退化到无毛色的 `eye_closed.png`（眼睑周围的毛色对不上）。

这是 R6「新增配色没同步派生件」的同类问题——R6 只对了 `traits.json` 的 values，
没覆盖表情件的毛色变体。

### 4.2 三个插槽的 anchor 是复制粘贴遗留

| 插槽 | anchor | 所属骨骼 | 距骨骼 |
|---|---|---|---|
| `ear_l_att` | **(660,450)** | ear_l (505,348) | 186 px |
| `ear_r_att` | **(660,450)** | ear_r (762,346) | 146 px |
| `tail` | **(660,450)** | tail_root (425,505) | ~240 px |

(660,450) 正是 `head` 骨的中点——三个插槽的 anchor 都被填成了 head 的位置。
ear 和 tail 的 anchor 应该分别是耳根 (505,348)/(762,346) 与尾根 (425,505)。

**对我方无影响**：耳朵/尾巴是整张全画布部件，直接绕骨骼 start 旋转，不读插槽 anchor。
但如果别的实现照 anchor 去定位附件就会错位，建议修。

### 4.3 附件命名契约（已由程序侧适配，供美术知悉）

`animations.json` 的 slot 值有两种写法，混在一起：

- 带毛色的完整名：`eye_round_blue`（主眼件，在 `Eyes/`）
- 不带毛色的裸名：`eye_closed` / `brow_angry_L` / `mouth_smile` / `blush`
  （表情件，在 `Expressions/`，多数带毛色变体）

即**同一个 slot 里，有的值带毛色、有的不带**。
程序侧已实现 `artmap.find_attachment()` 按「带毛色 → 裸名 → 主眼件」三档解析，
现在 0 个附件缺失。建议美术后续统一，否则下游每家都要自己猜。
