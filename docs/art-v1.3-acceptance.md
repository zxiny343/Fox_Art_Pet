## 三、发现的问题（按严重度）

### P0-A 细尾 / 短尾在尾根留下可见缺口（约 3.2–3.6 万像素）

用「母版轮廓内、组装后却透明」的严格判据逐个测（蓝狐、large 耳、round 眼）：

| 尾型 | 缺口像素 | 判断 |
|---|---|---|
| normal / triple / quint / nine | **0** | 正常 |
| fluffy | 777 | 可忽略 |
| twin | 1292 | 轻微 |
| long | 2055 | 轻微 |
| quad | 2679 | 轻微 |
| curl | 8295 | 偏大 |
| **short** | **32043** | **明显缺口** |
| **thin** | **35743** | **明显缺口** |

原因：body_core 把整块尾巴区都切成了窗口，`tail_base` 只兜住 socket（3181px），而尾巴窗口有 40294px。窄尾覆盖不满，缺口又**通向外部**（不是封闭洞），所以作者的 `repair_pockets`（binary_fill_holes）填不到，回归也查不出来（连通域仍是 1 个）。

影响：thin 是本次新加的、「蓬尾的反义」，也是 Tf 位点的另一半表达；不修等于这个性状不可用。

### P1-B 多尾根部出现深色碎片与接缝线（九尾最明显）

> **修订（2026-11-01 晚）**：原判 P0「堆叠成黑块」，实测后下调为 P1。
> 复核图 `docs/_probe_root_4x.png`（锚点周围 200×200、4× 放大）：问题真实存在，但规模是「几十像素的深色碎片 + 1–2px 白缝」，
> 1× 静态下不显眼；且「窗口暗像素占比」「模糊后低分位亮度」两种自动指标都区分不开正常与异常。
> 结论：不阻塞开工，仍建议修（放大显示与尾巴动画时会闪）。修单见 `docs/fox-art-fix-request-v1.4.md` §2。

9 条分支各自带 3–4px 深色描边，绕 tail_root 旋转复制后在根部互相叠压，形成一块被描边围起来的深色碎片，分支间还留下 1–2px 白色细缝。

black / obsidian_gold 这两种深色毛上不明显，但 orange / blue / white / mist_purple 上能看出来。

### P1 火焰纹偏「亮斑」而非「火焰」

作者自己声明：单色（light）+ screen 混合下辨识度中等。实测黑狐上确实可见，但更像不规则亮斑，缺少内焰暖色 → 想更好看需要允许双色（内焰暖色 + 外焰浅色）。

### P2 折耳耳内纹理轻微拉伸

弯曲处有色块拉伸，几何无断口。可接受。

## 四、这些缺陷挡不挡开工

**不挡。** 它们只影响观感，不影响「基因型 → 部件 → 合成」这条链路能否跑通。
但 P0-A 会让 thin/short 两个性状在正式版里不可用，P0-B 会让多尾（v0.6 验证过的核心进化载体）打折扣，所以建议作为 v1.4 小修单尽早回头补。
