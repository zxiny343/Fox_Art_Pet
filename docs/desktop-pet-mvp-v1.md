# 幻想小狐狸桌宠 —— 桌面外壳 MVP v1

> 2026-11-02 · 技术栈 **Python + PySide6**（不是 Electron/Spine，理由见 §7）
> 状态：**可运行**。三套自检 37/37 + 40/40 + 14/14，渲染 96 fps（30fps 目标留 3 倍余量）

---

## 1. 启动

```bash
python pet/app.py              # 正常启动（沿用上次的狐狸与位置）
python pet/app.py --new        # 换一只新狐狸
python pet/app.py --no-top     # 不置顶（调试/截图用）
python pet/app.py --fps 60     # 提高帧率
```

首次启动会自动贴到**屏幕右下角**（避开任务栏）。窗口 256×256。

## 2. 交互

| 操作 | 反应 |
|---|---|
| **左键拖拽** | 抓起狐狸（播 `drag`），跟着鼠标走 |
| **左键单击（不移动）** | 摸一摸 → 摇尾巴开心（`happy_wag`） |
| **左键双击** | 开心蹦跳（`happy_bounce`） |
| **滚轮** | 缩放（0.4× ~ 3.0×，以脚下为锚点，不会乱跳） |
| **右键** | 菜单：摸一摸 / 喂食 / 喝水 / 伸懒腰 / 嚎叫 / 换一只 / 睡一觉 / 置顶 / 鼠标穿透 / 退出 |
| **托盘图标** | 单击 = 摸一摸；右键 = 同上菜单；可显示/隐藏 |

**自动行为**（不需要你操作）：
- 呼吸待机 + 尾巴轻摆（常驻）
- 随机眨眼（平均 3.6 秒一次）、随机抖耳朵（平均 5.5 秒一次）
- **90 秒没理它 → 犯困**：坐下 → 趴下 → 睡觉；摸一下就醒
- 睡着时不再眨眼

## 3. 文件结构

```
pet/
  app.py              桌面外壳：透明置顶窗、拖拽、缩放、托盘、右键菜单
  behavior.py         行为状态机（纯逻辑，不依赖 Qt，可单独自检）
  config.py           配置持久化（位置/缩放/基因型/开关），坏配置自动退回默认
  verify_behavior.py  行为自检 37/37
  verify_pet.py       外壳自检 40/40（离屏，不打扰桌面）
```

状态存 `<项目>/pet_state.json`（下次启动还是同一只狐狸、同一个位置）。

## 4. 行为状态机是怎么设计的

美术侧的 36 个动作分三层，桌宠沿用这个设计：

| 层 | 规则 | 桌宠里装什么 |
|---|---|---|
| `base` | **同一时刻只有一个**（互斥） | `idle_breath` 常驻；交互时切 `happy_wag`/`eat`/`drag`… |
| `add` | 叠加在 base 上，可多个 | `idle_tail_sway` 常驻 + `idle_ear_twitch` 随机 |
| `face` | 覆盖，用于表情附件 | `blink` 随机 |

**关键点：每个动作必须有自己的播放进度。** 动画数据里所有动作共用归一化时间轴，
眨眼 0.4 秒、呼吸 4 秒——如果共用一个 `t`，眨眼会跟着呼吸一起循环，看起来像"每 4 秒眨一次而且是慢动作"。
为此给 `anim.py` 加了 `pose_at_multi([(aid, t_norm), ...])`，桌宠走这个入口，出 GIF 用旧的 `pose_at`。

睡眠是一条链，不是一次切换：

```
无交互 90s → sit_down(1.2s) → lie_down(1.6s) → sleep(常驻)
                                                    ↓ 被摸
                                              wake_up(2s) → idle_breath
```

## 4.1 整体变换：坐下 / 趴下 / 睡觉是怎么"沉下去"的

第一版做完时发现一个尴尬问题：**待机、摇尾巴、睡觉、被拖起四张截图长得一模一样**。
查下来是我的 rig 只实现了 7 根骨骼（尾 4 + 耳 2 + body 缩放），而 36 个动作一共驱动 20 根。

查骨骼层级后发现，**有 3 根骨骼不用切图就能补**，而且它们正好驱动最高频的几个动作：

| 骨骼 | 语义 | 关键动作 | 数值 |
|---|---|---|---|
| `pelvis[translateY]` | 整只狐狸升降 | 坐下 +96、趴下/睡觉 +150、蹦跳 ±22.5、起跳 −90 | 大 |
| `root[rotate]` | 整只狐狸旋转 | `drop` 14°、`roll_over` 360° | 中 |
| `body[rotate]` | 躯干倾斜 | 坐下 16°、邀玩鞠躬 22° | 中（**暂未实现**，见下） |

关键是 `pelvis` 的子孙**包含四条腿**（`hip→foot`、`shoulder→paw`），
所以 `pelvis translate` 的语义是「整只狐狸升降」而不是「躯干下沉腿弯曲」——整体平移就是正确实现。

**一个坑**：母版内容底边在 y=927，原 1024 画布只剩 96px 余量，
而趴下/睡觉要下沉 **150px**——直接做会把脚切掉。
所以动画画布**向下扩 192px**（1024×1216），桌宠窗口相应变成 1 : 1.1875 的非正方形。
（只改动画帧，静态渲染和 `render_kernel` 缓存都不受影响。）

`body[rotate]` 暂时没做：它是「躯干+头+前腿」一起转，但前腿和躯干在同一张位图里，
整体转会让狐狸歪 16°，看起来像摔倒而不是坐下。等分腿部件或 LBS 蒙皮再说。

## 5. 自检结果

| 套件 | 结果 | 覆盖 |
|---|---|---|
| `pet/verify_behavior.py` | **37/37** | 常驻层、随机眨眼（每次 13 帧=0.4s 不截断）、独立计时、交互回待机、拖拽、睡眠链、确定性、渲染对接 |
| `pet/verify_pet.py` | **40/40** | 窗口属性（无边框/置顶/不进任务栏/透明）、四角透明 62% 而本体 37%、帧率、缩放（含非整数 1.12×）、8 种交互、睡眠链、换只、配置持久化（含坏 JSON 兜底） |
| `sim/verify_anim.py` | 14/14 | 动画播放器（上一阶段） |

**性能**：单帧 10.4 ms → **96 fps**（work=256）。预算是 33 ms/30fps，留了 3 倍余量。
缩放放大到 2× 时 work 提到 512，帧率降到约 24 fps，仍够用。

**踩到并修掉的两个 bug**（都是静默型，症状不明显）：
1. `setFixedSize` 只吃 int，滚轮按 1.12 倍步进会产生小数 → 已 `int()` 并补测
2. 基因型存 JSON 后 `('K','k')` 变成 `['K','k']`。`phenotype()` 对两者结果一致，
   **但别处若有 `alleles == ('K','k')` 就会静默不等** → 在 `config.norm_geno()` 统一转回 tuple

## 6. 已知限制

| 限制 | 影响 | 什么时候解决 |
|---|---|---|
| **头部 / 脖子 / 口鼻 的旋转没实现**（点头、摇头、嚎叫、吠叫、进食、喝水、歪头） | 这些动作只剩尾巴耳朵在动 | 需要切割 `body_core`，切割线在颈点会露缝。**建议走 LBS 网格蒙皮**，不要硬切 |
| **四条腿的旋转没实现**（走/跑/跳/打滚） | 走路看不出迈腿 | 需要美术出分腿部件。**MVP 不需要** |
| 多尾（2–9 条）没有独立摆动相位 | 整条尾巴一起摆 | 需按角度扇区拆分同一张 PNG，待定 |
| `body[rotate]`（躯干倾斜）没实现 | 坐下/鞠躬不会前倾 | 见 §4.1，等分腿部件或 LBS |
| `eye_closed` 缺 `mist_purple` / `haze_blue` 两色 | 这两个毛色眨眼时会退化到无毛色版 | 已列入 v1.5 素材清单 |
| 鼠标穿透开启后无法拖拽 | 设计如此 | 靠托盘菜单关掉 |
| 生态引擎还没接进来 | 狐狸不会饿、不会长大、不会繁殖 | 下一步 |

## 7. 为什么是 Python + PySide6

不是"Qt 更好"，是三条具体理由：

1. **渲染是 PIL + numpy、生态引擎是 Python**，换成 JS 是纯损失；
2. 我原本担心的 Spine 优势**不成立**——`animations.json` 是我们自制的归一化时间轴 JSON，
   不是 Spine 的 `.json + .atlas`，`spine-webgl` 本来也读不了；
3. 桌宠只需要尾巴分段旋转、耳抖、呼吸缩放、眨眼切附件这类**刚性变换**，插值就够，不需要蒙皮。

窗口实现：`Qt.FramelessWindowHint | Qt.Tool | Qt.WindowStaysOnTopHint`
+ `WA_TranslucentBackground`，每帧 `render_frame` → `QPixmap` → `paintEvent`。
