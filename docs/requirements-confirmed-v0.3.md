## B. 你的回答带出来的新子系统

### B1. 取食系统：桌面文件即食物

> **这是整个项目里唯一会改动你真实数据的功能，所以规格写得最重。**

**被允许吃什么（三重门槛，全部满足才可食用）**

1. **位置门槛**：只能吃位于「投喂区」内的条目。投喂区是你显式指定的一个文件夹，默认**为空**（即默认一只字都吃不了）。
   - 桌面上其他位置的文件**永远不可食用**——它们最多被狐狸嗅探、扒拉、绕开，作为氛围互动，绝不删除。
   - 这条我想请你再确认一次：如果允许全桌面识别文件名，代价是"狐狸误吃你的论文.docx"这种不可挽回的事故随时可能发生（见 C1）。
2. **名称门槛**：投喂区内还需要匹配你设定的规则，例如 `*.tmp`、包含 `_old`、文件名形如 `Scrap*`。
3. **属性门槛**：非隐藏、非系统、非只读、未被其它进程占用、不在回收/同步冲突状态、大小 ≤ 上限（默认 10 MB / 个）。

**文件夹的处理**（你要求文件夹也能吃，所以做，但门槛更高）
- 默认**关闭**，需在设置里显式开启「允许吞噬文件夹」；
- 开启后仍必须满足：位于投喂区内、含文件数 ≤ 20、总大小 ≤ 50 MB、且不含任何隐藏或系统文件；
- 每次吞噬文件夹会弹出与 C1 相同的明细确认。

**删除方式：一律进回收站，绝不永久删除**
- 调用回收站 API，**不使用 `del` / `rm` / `DeleteFile` 直删**；
- 删除后立即可以用标准方式还原（回收站右键 / 程序内的"撤销这次进食"）；
- 每笔进食写入**取食日志**：时间、完整原始路径、大小、吃它的狐狸 ID、回收站内的位置。**这是可追溯的最后一道保险**。

**饱食三级状态（你要求不会饿死）**

| 饱食度 | 状态 | 表现 | 后果 |
|---|---|---|---|
| 100–60% | 活跃 | 正常行为、正常繁殖 | — |
| 60–25% | 低活跃 | 移动变慢、减少跑动、更多伏卧、不再主动求偶 | 繁殖欲望下降 |
| 25–0% | **休眠（torpor）** | 蜷缩、尾巴裹身、呼吸极缓、几乎不动，眼睛半闭 | 停止衰老推进（时间几乎冻结）、**不繁殖、不死** |

- 休眠可以无限持续，投喂后立即苏醒；
- 休眠个体仍然可点击、可查看、可直接投喂唤醒；
- **饥饿不是死亡原因**，这一点写死在系统里。

### B2. 离场与迁徙（非死亡退出）

| 项目 | 设计 |
|---|---|
| 定位 | 与「死亡」「退役」并列的第三种离桌方式，互不替代 |
| 触发条件 | 由个体自身状态驱动：**长期低活跃 / 连续求偶失败 / 健康偏低 / 年龄偏大**。拥挤度可作为加权因子，但**默认权重为 0** |
| 为什么拥挤度默认不加权 | 需求第七条写死"不因为达到数量上限就处理个体"。若让"达到上限"直接诱发迁徙，本质上就是变相的人口清除，违反该条。所以上限只压"出生"，不催"离场" |
| 表现 | 走到屏幕边缘 → 停下回头张望 3 秒 → 轻挥尾巴 → 淡出。全程约 8 秒，不给弹窗、不打断 |
| 记录 | 进入「迁徙名录」，保留完整基因型与亲缘，**后代溯源不受影响** |
| 回归 | 低概率「回乡」重返桌面（默认是极低概率，可调 0%；回归时带着原来的 ID 与基因型） |
| 迁徙者能否育种 | **能**，与纪念馆个体同待遇（见 B3 育种部分） |

### B3. 近交检测 + 纪念馆育种

**近交检测（你补充的 50% 放弃）**

```
触发交配意图 → 计算两只的亲缘系数 r（走谱系表，非活的也能算）
  r < 0.125        → 正常交配
  r ≥ 0.125        → 判定为近交 → 掷一次硬币
                        50% → 放弃本次交配（表现为"求偶被拒绝"，双方掉头走开）
                        50% → 继续交配，但后代隐性缺陷概率上升
```
- 阈值 0.125 ≈ 半同胞/表亲级别，可调（严格档 0.0625）。
- 隐性缺陷的表现：**先天虚弱**（健康上限 −、寿命 −、繁殖力 −），而不是当场死掉。
- 配对台必须显示：`亲缘系数 r = 0.25 ｜ 近交风险：高`，不让用户在不知情的情况下乱配。

**纪念馆育种（你新增的需求）**

你说的是：**喜欢的个体可以进纪念馆（它本人该死还是死），但它的基因可以被"承载"到现在的个体身上繁育**。

我的落地方式：

1. **取样**：个体生前（或死亡瞬间）可被标记为「种源」，生成一枚**基因样本**（快照其完整基因型）。
   - 活体也能取样，但每只一生有取样次数上限（默认 3 次）；
   - 样本是消耗品，用完为止。
2. **育种**：在育种台选择「基因供体（来自纪念馆）」＋「现存受体（活的）」→ 产生后代。
   - **后代基因完全按孟德尔生成**：把供体基因型当作一方亲本正常产生配子，与受体配子结合。因此**不绕过遗传规律**，和你第 4.3 条的要求一致。
3. **谱系标记**：后代的父亲/母亲指向供体，家谱树里用**虚线节点**标注 `DONOR`，并写明来自第几代。
4. **限制**（防止退化成"随便复活任何血统"）：样本数量有限 + 育种冷却时间 + 每次消耗。具体数值见设计稿 §17。
5. **近交检测同样适用**：供体参与 r 计算，防止反复用同一始祖近交刷血统。

### B4. 世界时钟：环境不绑死真实时间

```
真实系统 ─┬─ 壁纸/主题亮度 →【光照】即时读数（不改时间）
          └─ 用户设定流速 ─→【生态时钟 WorldTime】─→ 昼夜 / 季节 / 温度趋势
```

- **生态时钟**：1 游戏小时默认 = 1 真实分钟（可调），1 生态年默认 = 24 游戏天（可调）；与现实日历完全无关。
- 流速档位：暂停 / 1× / 2× / 5× / 10× / 自定义；加速同时驱动妊娠、成长、衰老、季节。
- **所有时间相关状态（饱食、妊娠、幼崽成长、寿命、季节、统计采样）必须走同一个时钟**，否则加速会带出一堆不同步的 bug。
- 每项都允许**手动覆盖**（例如锁死季节为冬），覆盖后 UI 打「手动」标。
- 环境面板总是显示当前：光照值 / 昼夜 / 季节 / 温度 / 食物丰度 / 拥挤度，以及各自的来源（自动 / 手动）。

### B5. 创始世代：开局 10 只幼崽

| 项目 | 设计 |
|---|---|
| 数量 | 10 只幼崽 |
| 亲缘 | 由 10 对虚构始祖分别产生，**彼此之间无亲缘**（r = 0），保证开局就能自由交配不触发近交 |
| 年龄 | 全是幼崽（统一接近成年边界），让玩家看到成长过程 |
| 夭折 | 照常适用幼崽夭折率（约 25–35%）—— 这是你的要求 |
| 我的补充建议 | 初始世代享受**「创始者保护」：夭折率按正常的 50%**（约剩 7–8 只成年）。理由见 C3。可在设置里关闭，改成完全硬核 |
| 性别 | 大致平衡，但由随机决定；极端情况下建议保底不少于 3♂3♀ |

## C. 我替你补的判断，以及还需要你点头的地方

### C1. ⚠ 关于「吃文件」的一道边界，请明确确认

你说"特定的文件夹、文件名字可以被当做食物"。**文件名/文件夹名可以在全桌面识别（只是识别，用于狐狸去嗅闻、围观），但真正允许删除（吃掉）的范围我建议严格限制在你指定的投喂区内。**

理由是删除不可逆（即便进回收站，用户也可能隔了很久才发现，回收站已被清空）。备选三档：

- **A（我的推荐）**：全桌面可识别可围观，**只吃投喂区内的条目**
- **B**：可在整个桌面吃符合文件名规则的文件（风险显著更高，误删可能不可恢复）
- **C**：只能在指定投喂区识别 + 吃（最保守，桌面上没有任何觅食氛围）

另外无论哪一档，这四条都不会让步：
① 只送回收站，**永不永久删除**；② 每笔记录**完整原始路径**的取食日志；③ 提供「撤销这次进食」；④ 隐藏文件 / 系统文件 / 只读文件 / 正在被占用的文件 / 超过上限大小的文件，一律不吃。

### C2. 「严酷模式」开关 —— 需要你确认是否提供

你要求"不会被饿死"，所以我默认饥饿只到休眠为止。是否要提供一个可选开关：

- **关闭（默认）**：长期饥饿只导致休眠、停止繁殖，**健康不再下降**
- **开启**：深度休眠超过一定时长后健康缓慢下降，可能病死 —— 等于把"饿死"放回系统

我倾向默认关闭并把它藏进高级设置，因为它实质上绕过了你刚定的规则。

### C3. 开局 10 只幼崽会不会太惨

如果 35% 夭折率直接打满，开局很可能只剩 6 只左右，而剩下的一旦性别失衡（比如 1♂5♀），前期就直接卡死。所以我在 B5 里加了「创始者保护」减半夭折率，并建议保底性别。这条如果你要完全硬核，划掉即可。

### C4. 由你的选择产生的连锁影响（已经在设计稿里改好了）

1. **饥饿不再是死亡原因** → 自然选择的主压力改为：**疾病 / 衰老 / 幼崽夭折 / 繁殖竞争**，以及环境 × 基因型的适应度差。设计稿 §8.0 的适应度表已按此重排。
2. **Q9C 幼崽死亡率高** → 与合作最大种群上限形成天然的负反馈（不用刻意限流）。
3. **Q2A 自主死亡 + Q7 离场并存** → 死亡不再是唯一终点，但只有死亡才真正结束一条血统（离场仍保留座位），这个区分要在 UI 上表达清楚。
4. **Q11 快照不存位置** → 恢复后坐标重新随机散布，配合"狐狸活动本身就是随机的"这条设定，观感上没有损失；同时也意味着**不需要写动画序列化**，存档体积很小。

### E3. 边界（不做什么）

- 面板**只显示不干预**：概率是真实配子随机组合的结果，看到 25% 就是 25%。
- 不能指定后代基因型（§5 红线不变）；人工只能决定「谁和谁生」「每窝多少仔」。
- 不提供绕过密度约束的入口（ρ ≥ 1 时配对按钮置灰，Q16）。
- 概率不含突变（3%/仔另计），界面需注明。
- 40 只种群不做每帧全量重算，仅在打开面板 / 更换选择时计算。
