### LOCK-C 姿态说明（v1.1 已改定）

**四足着地站姿，3/4 前侧朝向。** 头部在前上方微微抬起看向观者，尾巴在身后向左后方卷起。

改为四足的依据（实测证据，非猜测）：
- 两轮共 8 张候选，模型**全部**倾向四足或斜立，只有 1 张勉强接近二足；
- 追加"不要四足着地/爬行/趴伏/蹲坐"等显式否定词后仍无改善，说明是模型的动物先验而非提示词表述问题；
- 四足姿态下模型出图质量与稳定性显著更好。

**代价已确认接受**：前肢不再参与互动，互动动作改由**头、耳、尾、身体整体姿态**表达
（点头、歪头、耳朵抖动、尾巴大幅摆动、身体起伏、原地小跳）。
这不影响 `tail_root` / `neck` 唯一锚点的复用原则，也不影响遗传性状替换。

| 项 | 值 |
|---|---|
| 母版尺寸 | 1024 × 1024 px |
| 色彩 | RGBA 8-bit/channel，sRGB，含 alpha |
| 背景 | 完全透明（alpha = 0），**禁止**任何白底/灰底/棋盘底残留 |

## 3. 比例锁（LOCK-B）

> 相对 v0.1 草案的调整：**头高 240 → 300、躯干 260 → 180、腿 128 → 148**。
> 调整理由：v0.1 的头身比偏写实，不满足"头部略大、身体小巧"。
> **外围包络未变**（耳尖 y=150、地面 y=928、总高 778），只改内部分段，已出的构图不受影响。

| 分段 | 起止 y | 高度 | 说明 |
|---|---|---|---|
| 耳 | 150 → 300 | 150 px | 耳尖 → 头顶（耳根） |
| 头 | 300 → 600 | 300 px | 头顶 → 下巴，含颊毛 |
| 躯干 | 600 → 780 | 180 px | 肩/颈根 → 髋部 |
| 腿 | 780 → 928 | 148 px | 髋 → 地面 |
| **总高** | 150 → 928 | **778 px** | 脚底 → 耳尖 |

宽度锁：

| 项 | 宽度 | x 区间（中心 512） |
|---|---|---|
| 头部（含颊毛） | 340 | 342 – 682 |
| 躯干 | 240 | 392 – 632 |
| 肩宽 | 240 | 392 – 632 |
| 髋宽 | 230 | 397 – 627 |

头身比校验：头高 300 ÷（躯干 180 + 腿 148）= **0.91**，头 + 耳占全高 **58%** —— 属于标准 Q 版吉祥物比例。

> ⚠️ 上表为**二足方案遗留存档**（v1.0），自 v1.1 起姿态改为四足，竖直分段不再对应解剖结构，
> 实际出图以 §3.1 四足包络规则为准。保留此表是为了二创时能还原早期方案。

### 3.1 四足站姿包络规则（v1.1，现行）

1. 内容在 **904 × 904 安全框**内等比最大化（不撑出 60 px 安全边距）；
2. 内容**底边贴 y = 928**（地面接触线）；
3. 内容**水平居中于 x = 512**；
4. 由此，四足姿态下内容高度通常小于 778，**耳尖 y 不再固定为 150**，这是预期行为。

四足参考比例（母版单位，待阶段 1 首图实测后回填精确值）：

| 项 | 目标值 | 说明 |
|---|---|---|
| 背线高度 | y ≈ 600 | 肩/背部最高处 |
| 腹线高度 | y ≈ 790 | 腹部最低处 |
| 腿高 | ≈ 138 | 腹线 → 地面 |
| 头高 | ≈ 220 | 头顶 → 下巴 |
| 体长（鼻尖 → 尾根） | ≈ 640 | 水平方向 |

**所有遗传变体必须落在同一包络内**。允许变化的是轮廓细节（毛发长短、耳朵大小、尾巴形态），**不允许**变化的是包络规则与地面接触线。体型差异（大/小个体）只允许通过程序整体缩放 0.85 / 1.0 / 1.15 实现，美术侧**不**出三套体型。

> **⚠ v1.2 修订（2026-11-01 用户拍板，以上第 5 条已作废一半）**
> 包络规则改为 **「身体核心对齐」**：`body_core` 的坐标 / 尺寸 / 锚点必须全毛色统一
> （实测 bbox `(189,150)-(877,928)`，10/10 毛色一致）；
> **耳朵与尾巴允许突破统一包络**（实测 tail_twin 左越框 14px，属正常），
> **禁止为对齐包络而对部件做整体缩放**——那会压缩性状差异。
> 唯一强制项改为「不得出血：组装后 bbox 离画布边 ≥ 4px」。
> 详见 `00_Spec/08_包络v1.2与尾巴分层方案.md`。

### 锚点铁律
1. **`tail_root` 唯一**：长尾/短尾/蓬松尾/卷尾/双尾全部共用同一个 `tail_root`，只改骨骼段数与末端位置。这是"一套动画复用给所有个体"的唯一保证。
2. **`neck` 唯一**：头身只有一个连接点，任何头型变体不得移动它。
3. 锚点是**命名与坐标系契约**，数值允许在阶段 1 出图后按实测微调 ±12 px；一旦进入阶段 2（遗传性状），数值冻结，之后只允许改部件不改锚点。

## 5. 艺术风格规范（LOCK-D）

### 5.1 造型
- 2D 卡通 Q 版，头部略大、身体小巧，轮廓圆润饱满，不出现尖锐写实结构。
- 耳朵大而有辨识度，耳内与耳背明确分色。
- 尾巴是核心识别特征，蓬松、体积感强，占身体视觉比重不低于 35%。
- 眼睛大而有神，高光为固定两点（左上大高光 + 右下小高光），位置统一。
- 四肢短小圆润，爪部简化为 3 趾（前爪）/ 简化椭球（后脚），不画写实趾甲。
- 禁止：写实解剖、复杂机械结构、拟真透视、过度装饰、金属/玻璃硬表面材质。

### 5.2 描边（LOCK-E）
- **自适应深色描边**：颜色 = 该区域毛色的暗部再降 25% 明度，**禁止纯黑**、禁止统一用一个颜色描所有部件。
- 母版线宽 6 px，外轮廓 6 px，内部结构性分隔线 4 px，装饰性细线 2–3 px。
- 描边闭合、无断线、无毛刺、无双线重叠。
- 部件拼接处的描边允许互相压盖 —— 这是选深色描边的核心收益，替换件接缝天然被隐藏。

### 5.3 光照与明暗
- 统一光源：**左上 45°**，所有素材一致，禁止某些部件光从右来。
- 三段明暗：亮部（`#light`）／主色（`#base`）／暗部（`#shade`），暗部集中在右下与部件相互遮挡处。
- 阴影用**实色块 + 硬边**（卡通赛璐璐），不用软渐变、不用叠加正片低透明度的灰。
- 高光只出现在：眼睛、鼻头、耳内边缘、尾尖、毛发顶部轮廓。**数量克制**。

### 5.4 毛发质感
- 蓬松感靠**轮廓的锯齿/波浪起伏**表达，不靠内部杂乱线条。
- 内部只保留 3–5 组方向性毛簇线，且必须跟随体表走向。
- 短毛 / 中长毛 / 长毛 / 卷毛的**轮廓必须可辨识**（见 `03_配色与性状字典_v1.0.md`）。

### 5.5 禁止项（AVOID）
- 伪文字（图中出现不可读的假字、乱码字符）。
- 未授权品牌标识、他人 IP 特征。
- 背景元素、地面阴影盘、投影、场景道具（角色层内一律不画）。
- 半透明毛发的"果冻感"、镜头光晕、粒子特效（特效层单独出，不进角色层）。
- 纯色块平涂换色造成的塑料感。

## 6. 命名规范

### 6.1 文件命名
`{部件}_{性状ID}_{变体}[_{左右}].png`

- 全小写，下划线分隔，禁止空格与中文。
- 左右件后缀 `_l` / `_r`（小写）。
- 示例：`ear_pointed_blue_l.png`、`tail_fluffy_purple.png`、`eye_almond_gold_r.png`。
- 默认值省略变体段：`body_base.png`（即默认霜蓝短毛躯干）。

### 6.2 性状 ID
`{类别}_{具体值}`，类别取值：`coat`（毛色）`ear`（耳）`tail`（尾）`eye`（眼）`fur`（毛发）`pattern`（花纹）`special`（特殊）。
示例：`coat_orange`、`ear_round`、`tail_twin`、`eye_hetero`、`fur_curly`、`pattern_stripes`、`special_glow`。

### 6.3 图层命名（PSD / layers.json）
与导出文件一一对应，分组用英文：`Head / Body / Tail / Limbs / Special`，组内图层名 = 文件名去扩展名。禁止 `图层 1`、`图层 2 副本`。

## 7. 导出规范

1. 部件**一律按母版全画布 1024 导出**（不裁切），保证程序叠加零错位。
2. 另出 trim 版（自动裁到内容边界）+ `offsets.json` 记录 `{x, y, w, h, offsetX, offsetY}`，供图集打包用。
3. 透明底，alpha 干净：**无白边、无半透明灰边、无抗锯齿脏点**。抠图后统一做 1 px 内缩侵蚀再回填，杜绝白边。
4. 边缘 2 px 内不得出现与主体无关的颜色。
5. 三档尺寸由母版**等比下采样**生成（512 = 0.5，256 = 0.25），不重新绘制。
6. 每张图出图后必须通过 §8 红线清单检查，不通过不入库。

## 9. 第三方二创（Mod）规范

1. 二创部件**必须**声明它依赖的 `anchorSet` 版本（当前 `anchorSet = v1.0-view34`）。
2. 二创部件可以改外形、改配色、加装饰，但**不得移动** `root / neck / tail_root / pelvis` 四个锚点。
3. 新增部件放入 `Fox_Art/mods/{作者}/{类别}/`，附 `manifest.json`：
   ```json
   {
     "modId": "mochi_tail_candy",
     "anchorSet": "v1.0-view34",
     "category": "tail",
     "replaces": "tail_normal",
     "boneSegments": 3,
     "files": ["tail_candy_l.png", "tail_candy_r.png"],
     "author": "mochi",
     "license": "CC-BY-NC 4.0"
   }
   ```
4. 二创素材与官方素材在运行时**同权**，程序按 manifest 顺序加载，后加载覆盖先加载。
5. 官方保留拒绝权：含未授权 IP、侵权素材的 mod 不进入默认加载列表（由程序侧配置控制，美术侧只做标记）。

## 10. 生产管线与能力边界（必读）

| 环节 | 能力 | 说明 |
|---|---|---|
| 概念锚图、部件分解图、配色样张 | **可灵生成** | 栅格 RGB 输出，1k/2k |
| 透明底 PNG | 本地 Python 后处理 | 抠图 + 去背 + 侵蚀去白边 |
| 规整到 1024 画布 / 锚点对齐 | 本地 Python（PIL / numpy） | 按 §4 锚点仿射对齐 |
| 分层 PSD | 本地脚本合成（psd-tools） | 图层顺序来自 `01_Data/layers.json` |
| 512 / 256 导出 | 本地 Python | 等比下采样 |
| 骨骼绑定 | **下游** | 本阶段只交付骨骼建议 + 锚点 |
| 动画制作 | **下游** | 本阶段只交付关键帧参考与分解图 |

**已知限制（不掩饰）**：
- 可灵不产出透明底、不产出分层文件、不产出按锚点对齐的部件图。上述能力全部由本地后处理实现，误差来源主要是抠图边缘质量。
- 若某部件无法从整图中干净分离（例如长毛与躯干交缠），该部件会改为**独立重绘**（以整图为参考单独出图），并在部件清单中标注 `source: redraw`。
- 分层 PSD 若本机缺 `psd-tools`，降级为「独立部件 PNG + `layers.json` + 合成脚本」，交付时会明确标注降级，不冒充 PSD。
