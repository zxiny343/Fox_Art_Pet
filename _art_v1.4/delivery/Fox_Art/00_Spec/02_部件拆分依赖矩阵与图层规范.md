## 2. 依赖矩阵（可替换 vs 成套 vs 不兼容）

### 2.1 成套替换（Tier-2 组）

| 组 | 成员 | 触发条件 |
|---|---|---|
| `SET_EAR` | 外耳 + 耳内 + 耳尖高光 | 换耳型时整组换 |
| `SET_EYE` | 眼球 + 眼睑 + 瞳孔高光 | 换眼型时整组换；换眼色只需换眼球 |
| `SET_FUR_HEAD` | `head_base` + `cheek_fluff` + `back_fur` | 换毛发长度时整组换 |
| `SET_FUR_BODY` | `body_base` + `chest_fluff` + `back_fur` + 四肢外轮廓 | 同上 |
| `SET_FUR_TAIL` | 主尾 + `tail_fur_*` | 同上 |

### 2.2 不兼容组合（Forbidden）

| 组合 | 原因 | 处理 |
|---|---|---|
| `fur_curly` × `pattern_stripes` | 卷毛轮廓起伏会把条纹切碎，256 档糊成一团 | 程序侧禁用；或条纹降为稀疏大斑 |
| `tail_twin` × `tail_short` | 概念冲突（双尾与短尾互斥） | 互斥，程序侧单选 |
| `tail_twin` × `tail_curl` | 双尾 + 螺旋骨骼分支过深，绑定成本失控 | 互斥 |
| `ear_small` × `special_ear_star` | 星形缺口在小耳上无法辨识 | 互斥 |
| `fur_long` × 使用 `body_base`（默认件） | 长毛轮廓会超出默认躯干外框造成断层 | 强制换成 `body_base_long` |

### 2.3 遮挡顺序（从下到上）

```
special_aura          (最底，加法)
back_fur
tail_*                (主尾在躯干之后)
body_base
leg_back_l / leg_back_r
belly
chest_fluff
arm_front_l / arm_front_r
paw_front_l / paw_front_r
head_base
cheek_fluff
ear_inner_*  → ear_*
forehead_mark
eye_*  → eyelid_*  → brow_*
nose_*
mouth_*
special_star_mark
special_glow          (最上，加法)
```

**注意**：尾巴在躯干**之后**（3/4 视图下尾巴从身后扫出），但尾巴的发光层仍在最上。

> **v1.2 已落地实现**：现行管线（`run_assemble.py`）的实际图层顺序为
> `Tail_Base → Tail → Body_Core(+Pattern) → Ear_L → Ear_R → Eye_L → Eye_R`。
> body_core 带透明窗口、接缝归身体、socket 兜底，详见
> `00_Spec/08_包络v1.2与尾巴分层方案.md`。下面的 PSD 树仍是**目标结构**，
> 交付的 `assets/source/Fox_Base.psd` 为当前已拆出的 8 层实测结构。

## 3. 骨骼依赖标记

| 部件 | 骨骼 | 说明 |
|---|---|---|
| 头 | 1 旋转骨（`neck`）+ 1 缩放骨（`head_center`） | 点头的旋转中心在 `neck` |
| 耳 | 每耳 1 旋转骨（`ear_root_*`），可做 2 段（耳根 + 耳尖） | 耳抖用 2 段 |
| 眼 | 无独立骨，靠眼睑层切换 + 眼球 UV/位移微动 | 眨眼为层切换，非骨骼 |
| 尾 | 链式骨，段数见 §1.3 | **所有尾型共用 `tail_root`** |
| 四肢 | 每肢 2 段（肩/髋 → 爪/脚） | 走路/跳跃用 |
| 身体 | 1 呼吸骨（`pelvis` 缩放/位移） | 呼吸、伸懒腰 |
| `tail_twin` | **S 级**：需在 `tail_root` 下开两个分支，各 3 段 | 见下 |

### 双尾（tail_twin）处理方案
- 不新建根节点，仍在 `tail_root` 下分叉为 `tail_root_a` / `tail_root_b`，各自 3 段链。
- 两根尾巴的**默认夹角 28°**，动画复用普通尾的曲线数据，按 ±14° 偏移播放，避免相位完全同步导致的机械感。
- 代价：双尾个体的尾巴动画需要一次分支偏移计算，程序侧约 20 行代码。**不需要重做整套动画**。
- 美术侧交付：两张独立 PNG（`tail_twin_a.png`、`tail_twin_b.png`）+ 一个 `manifest` 声明 `boneBranches: 2`。

## 5. 部件来源标记（诚实交付用）

每个部件在 `parts.json` 中带 `source` 字段：

| 值 | 含义 |
|---|---|
| `extract` | 从整图中干净抠出的层 |
| `redraw` | 无法干净分离，以整图为参考单独重绘的层 |
| `synthetic` | 由脚本生成（如色相映射产生的换色件） |
| `manual` | 需人工修整的层（交付时会列出清单） |

**交付时若存在 `manual` 未完成的层，会明确列出，不用 `extract` 冒充 `redraw`。**
