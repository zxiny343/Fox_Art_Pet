## 一、包络规范改为「身体核心对齐」（v1.2）

### 1.1 修订原因
v1.1 的包络规则要求所有部件都装进统一安全框，导致**极端性状被压缩**：
长尾、大耳、双尾这类"本来就该夸张"的性状，为了不越框被迫整体缩小，
结果是"性状差异在最终画面上被抹平"——这与繁殖/变异系统的设计目标直接冲突。

### 1.2 新规则
| 对象 | 是否强制对齐统一包络 | 约束 |
|---|---|---|
| **body_core（身体核心）** | ✅ 强制 | 坐标、尺寸、锚点全毛色完全一致 |
| 耳朵 ear_L / ear_R | ❌ 允许突破 | 根点锚点固定，尺寸/轮廓随性状自由 |
| 尾巴 tail | ❌ 允许突破 | 根点锚点固定，长度/形态随性状自由 |
| 花纹 / 特殊件 | ❌ 允许突破 | 按叠加层处理 |

**铁律：不得为了对齐包络而对部件做整体缩放。** 部件一律以 1024 全画布
`(0,0)` 叠加，尺寸即原画尺寸。

### 1.3 身体核心统一性实测（10 套毛色）
```
body_core bbox = (189,150)-(877,928)   面积 = 240020 px    ← 10/10 毛色完全一致
```
由 `tools/probe_envelope.py` 输出，每次改母版都必须重跑并保持这一行不变。

### 1.4 越框白名单（实测）
| 部件 | bbox | 越框情况 |
|---|---|---|
| tail_twin | (133,296)-(503,506) | 左越框 14px —— **允许**，这是双尾应有的体量 |
| tail_long / fluffy / curl | (162..196, 259..326)-(503,506) | 包络内 |
| ear_*_R | 最远 x=841 | 包络内 |

唯一强制项改为 **不得出血**：组装后 bbox 必须离画布边 ≥ 4px
（`run_batch.py` 的 `noClip` 检查）。

## 二、尾巴分层方案：身体下层（3/4 视角默认在身后）

### 2.1 图层顺序（自下而上，已写入代码与 PSD）
```
1  Tail_Base    基础尾根兜底件（可选，见 2.4）
2  Tail         可替换尾巴（性状件）
3  Body_Core    身体核心（含尾巴透明窗口）
4  Pattern      花纹遮罩（clip 在身体上）
5  Ear_L
6  Ear_R
7  Eye_L
8  Eye_R  (+Pupil)
```
尾巴在身体**之下**，因此在 3/4 视角下：尾巴绕到身后的部分会被躯干/后腿正确遮挡，
且未来任何"尾巴压在身前"的表现只需把该尾件移到 Body_Core 之上即可，不用改资产。

### 2.2 body_core 的透明窗口
- 窗口 = `split_regions.json#regions.tail ∩ 母版alpha`，面积 **40294 px**。
- **窗口不做膨胀**（`noDilate`）：使 `body_core` 与 `tail` 部件**像素级互补**，
  合成后零缝、零白边、零半透明边。
- 窗口是透明的：尾巴从下面透上来，所以视觉结果与母版一致。

### 2.3 统一 socket 锚点 + 接缝归身体（防破洞的核心）
窗口内有一圈"贴着身体"的像素，如果留成透明而变体尾巴没盖住，
就会在臀部/后腿边留下一条透明缝。处理方式：

```
seam  = 窗口 ∩ dilate(body_core, 4)        # 2129 px，沿身体法线 4px 深
归属  = seam 归 body_core，做 socket 补色（不透明邻色扩散）
socket = dilate(seam, 2) ∩ 窗口             # 3181 px，写入 tail_socket_mask@1024.png
```

效果：尾巴根部自然插进身体后面；**任何尾型都不会露透明洞**（短尾也不露）。

### 2.4 基础尾根兜底件 tail_base（可选保险）
- 文件：`assets/master/Tails/tail_base_<coat>@1024.png`（10 套毛色）
- 覆盖 socket 再外扩 3px，**对 socket 覆盖率 100%**
- 用于 `seam="window"` 模式（整块窗口全透明、需要尾件自己撑住连接处时）。
  默认 `seam="socketfill"` 模式不需要它，但它随包交付，作为扩展保险。
- 覆盖率实测（叠加 tail_base 后全部 1.000）：

| 尾型 | 单独覆盖 socket | + tail_base |
|---|---|---|
| normal | 1.000 | 1.000 |
| long | 1.000 | 1.000 |
| fluffy | 1.000 | 1.000 |
| curl | 0.942 | 1.000 |
| **short** | **0.506** | **1.000** |
| twin | 0.954 | 1.000 |

### 2.5 封闭口袋修补（repair_pockets）
双尾在臀部围出的封闭缺口（实测 565px，与身体范围内重叠 47px）会被
`run_assemble.repair_pockets()` 用邻色补上。只补**窗口内被不透明像素围住**的口袋：
短尾 distal 区是开放到背景的正常留白，不会被误填成一条长尾。

## 三、三种方案对比（为什么选现在这套）

`tools/run_tail_modes.py` 输出 `09_Review/_tail_modes.png`（6 种尾型 × 3 方案）：

| 方案 | 做法 | 结论 |
|---|---|---|
| A | 尾巴压在身体上（阶段3旧方案） | 卷尾/双尾出现生硬重叠，短尾断成 3 个连通块 |
| B | 整块透明窗口 + tail_base 兜底 | 尾根普遍有透明缝/发白断块，最差 |
| **C** | **接缝归身体 + socket 补色（现行默认）** | **全部尾型衔接顺滑、零破洞、单连通域** |

客观指标（8 组性状组合，`run_batch.py`）：
```
comps=1  noClip=True  coreBbox=True  bodyHoles=0     → 8/8 PASS
```
