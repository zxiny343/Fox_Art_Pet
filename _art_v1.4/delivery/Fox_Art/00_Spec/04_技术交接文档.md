## 10.4 动画说明

### 三个方案的评估 `[已确定 - 初评]`

| 维度 | Sprite Sheet | Spine 2D | Live2D |
|---|---|---|---|
| 部件独立运动 | 不支持（整图替换） | **支持**（骨骼 + 插槽换图） | 支持（网格变形） |
| 遗传性状替换 | 灾难（每种组合一张表） | **原生支持**（同插槽换附件） | 支持但需逐个模型重制 |
| 大量外观组合 | 不可行（20 万组合） | **可行**（运行时拼装） | 可行但成本高 |
| 制作成本 | 低但量巨大 | 中（一次绑定，永久复用） | 高（每只都要重调） |
| 下游程序影响 | 简单但包体爆炸 | 需接入 Spine 运行时 | 需接入 Cubism 运行时 |
| 尾巴/耳朵独立运动 | 需逐帧画 | **原生** | 需变形器 |

**推荐：Spine 2D**（或等价的分层 + 骨骼运行时，如自研 / DragonBones）。
理由：本项目的**组合数是 20 万级**，唯一能落地的方案是"运行时按基因拼装部件 + 一套骨骼动画"。Spine 的插槽/附件机制正好对应我们的部件替换，`tail_root` 唯一锚点正好对应它的骨骼链。
**备选**：若不接受 Spine 商业授权，用"分层 PNG + 自研简易骨骼（2D 变换树）"也能达到 90% 效果，我们交付的锚点 JSON 就是为这条路线准备的。
**不推荐**：Sprite Sheet（包体不可行）、Live2D（每只重制，与遗传系统冲突）。

### 基础骨骼结构 `[已确定 - 建议]`

```
root (512,928)
└─ pelvis (512,780)
   ├─ tail_root (430,762) → tail_mid → tail_tip      [2–5 段，按尾型]
   ├─ hip_l → foot_l                                  [2 段]
   ├─ hip_r → foot_r                                  [2 段]
   └─ neck (512,600)
      ├─ head_center (512,450)
      │  ├─ ear_root_l → ear_tip_l                    [1–2 段]
      │  ├─ ear_root_r → ear_tip_r                    [1–2 段]
      │  ├─ eye_l / eye_r                             [无骨，层切换]
      │  └─ muzzle                                    [无骨]
      ├─ shoulder_l → paw_l                           [2 段]
      └─ shoulder_r → paw_r                           [2 段]
```

**动画复用铁律**：所有动作只驱动这棵树。任何变体（长尾/双尾/长毛/大耳）都**不新建骨骼**，只改段数与末端偏移。呼吸/眨眼/耳朵抖动这类"层切换 + 微位移"不占用骨骼。

## 10.5 性状组合说明 `[已确定]`

- 性状 → 素材映射：见 `01_Data/traits.json`。
- 可自由组合：毛色 × 耳型 × 尾型 × 眼色 × 眼型 × 瞳孔 × 花纹 × 特殊（特殊可叠加）。
- 不兼容组合：见 `traits.json → incompatible`，程序侧必须拦截。
- 特殊性状处理：全部为独立叠加层 + `stackable: true`，程序按开关叠加，不写入基础图。
- **体型差异不出美术素材**，用整体缩放 0.85 / 1.0 / 1.15 实现。

## 10.6 下游实施建议（给下一个 AI 的具体动作）

1. **导入素材**：读 `01_Data/parts.json`，按 `bbox` 全画布 1024 直接叠加，零偏移。打包图集时用 `trim` + `offsetX/Y` 还原位置。
2. **组合一只狐狸**：
   ```
   phenotype = { coat, ear, tail, eyeShape, eyeColor, pupil, fur, pattern, special[] }
   → 按 traits.json 解析出部件文件列表
   → 按 02 文档 §2.3 遮挡顺序从下到上绘制
   → 若 fur in [long, curly] 则强制替换 body_base / head_base 为 _long 版本
   → 校验 incompatible 列表，冲突时回退到 default
   ```
3. **替换遗传性状**：只换对应槽位文件，不动其他层。**换耳型换 SET_EAR 整组，换眼型换 SET_EYE 整组**，只换眼色则只换眼球层。
4. **建立动画骨骼**：按 §10.4 骨骼树，直接读 `anchors.view34.json` 生成节点坐标，**不要手填坐标**。
5. **复用基础动画**：一套动画文件（如 `idle.json` / `walk.json`）作用于全部个体。双尾个体在 `tail_root` 下开两个分支、各偏移 ±14° 播放同一条曲线即可。
6. **换色**：运行时用 `colorways.json` 的 remapRules 对明暗层做色相映射；已提供 10 色的成品色板，优先直接用成品色板而非运行时计算。
7. **还需要进一步制作的**：正面视图、侧面视图（阶段 3）；全部动作关键帧（阶段 4）；表情 10 种（阶段 4）；8 种个体 + 亲代/后代演示（阶段 5）；`parts.json` 完整填充（阶段 3）。
